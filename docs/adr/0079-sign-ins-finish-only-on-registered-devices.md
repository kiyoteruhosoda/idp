# ADR-0079: 登録した端末からだけログインを終わらせる（組織の設定）

- Status: Accepted
- Date: 2026-11-06
- 関連: task #916（親 #867「宅内への侵入に気付けるようにする」）、ADR-0071（自分の端末）、ADR-0074（DBSC）、
  ADR-0077（アプリで続ける）、ADR-0058（テナントが決める設定）

## 背景

持ち主の決定（11/06）: 家の中も外と同じ扱いにする。Wi-Fi は誰が使ってもよいが、Nolumia には入れない。VPN は使わない。
その一段上の守りとして、パスワードが漏れても、登録していない端末からは入れないようにする。

ADR-0071 は登録していない端末でのログインを**知らせる**だけで、ログインそのものは通していた（判定はログインの後に
web の middleware が行う）。

## 決定

1. **組織の設定 `REGISTERED_DEVICE_REQUIRED`（既定 false。利用者の所属元の組織で決まる）を足す。** 有効な組織の人は、
   今のブラウザの端末の印が自分の登録済みの端末であるか、認証アプリで承認したとき（ADR-0077）にしか、SSO セッションが
   作られない。**家の中か外かは見分けない**（ネットワークの場所は判定に使わない）。
2. **断る所は SSO セッションを作る所の手前の 1 つの関門（`DeviceGate`）。** 6 経路が通る
   `SignInCompletion::establish_sso_with_binding` と、自分で SSO を作るポータル・管理コンソールの 2 か所が呼ぶ。結果は
   型（`Establishment::DeviceEnrollmentRequired`）で返すので、扱わない経路はコンパイルが通らない。設定を読めない・端末を
   引けないときはエラー（ログインは成立しない側）。
3. **端末の印は web が要求の前に決め、内部の呼び出しの見出し `x-assay-client-device` で渡す**（task #895 の国と同じ形）。
   api は `/internal/*`（サービストークンの内側）でだけ読む。初めてのブラウザでも、web がその場で印を作って渡す
   （Cookie に置くのは、応答がログイン状態か登録の札を置いたときだけ）。
4. **登録していない端末で正しく認証した人には、SSO の代わりに 10 分の「登録の札」を返す。** 札は DB に置かない署名付きの値
   （`CSRF_SECRET` から用途で分けた鍵の HMAC。中身は要求の組織・利用者・**端末の印の指紋**・確かめた方式・期限）。
   web は札を Cookie に置いて `/{t}/device-enrollment` へ回す。画面で**その人のパスキー**で確かめると、そのブラウザを
   端末として登録し、そこで SSO を作って元の画面へ戻す。札は別のブラウザでは開かず、札だけでは何もできない
   （パスキーが要る）ので使い切りにしない。
5. **知らせ**: 関門が断ったとき（`login.unregistered_device_refused`・「正しく行われかけた」）と、端末を登録したときは、
   `UNREGISTERED_DEVICE_ALERTS_ENABLED` に関わらず送る。前者はパスワードが漏れた合図になりうる。
6. **締め出しを避ける**:
   - 有効にするのは選ぶときに確認を挟む値（`locks_out`）。加えて、その組織に**登録した端末も認証アプリの鍵も無い有効な人**が
     居るうちは、有効にする保存を断る（名前を返す）。
   - break-glass の口座は所属元が root（ADR-0070）。root では有効にしないので、どの端末からでも入って設定を戻せる。
   - 既にあるログイン状態は切らない（長くても 7 日。結び付いたものは 30 日）。
7. **Windows の Chrome はパスキーだけで登録できる**（スマホのアプリを要しない）。DBSC（ADR-0074）は登録の条件にしない。
   スマホは「アプリで続ける」か、ブラウザをパスキーで登録する（持ち主の決定 11/06・B 案）。

## 結果

- パスワードが漏れても、登録していない端末からはログインが終わらない。そのたびに知らせが鳴る。
- ⚠ **防げないこと**: パスキーそのものを盗まれた場合（例: 同期されたパスキーのアカウントを乗っ取られる）は、新しい端末を
  登録されてしまう（「端末を登録しました」が鳴る）。登録済みの端末そのものの乗っ取り・端末の印の持ち出し（ADR-0071 と同じ）。
- Cookie を消す・シークレットウィンドウ・別のブラウザは毎回「登録していない端末」になり、パスキーで登録し直す。
- パスキーを持たない人は、登録した端末を失うと自分では戻れない（管理者が設定を一時的に戻す。OPERATIONS.md）。
- 不採用: 「新しい端末の登録は登録済みの端末で承認したときだけ」（最初の 1 台と、Windows だけで完結する前提に合わない）。
  スマホは認証アプリだけ（A 案。パスキーを盗んだ人はパソコンで登録できるので守りが増えず、締め出しの道だけ増える）。
