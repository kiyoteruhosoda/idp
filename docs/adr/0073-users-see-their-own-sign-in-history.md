# ADR-0073: 本人が自分のログイン履歴（接続元・端末・入り方・リフレッシュの利用）を見られるようにする

- Status: Accepted
- Date: 2026-11-04
- 関連: task #879（親 #867「宅内への侵入に気付けるようにする」）、ADR-0071（登録していない端末でのログインの知らせ）、
  ADR-0044（セッションの失効で refresh token も落とす）

## 背景

不審なログインに本人が気付く材料が画面に無かった。記録はあちこちにあるが、どれも本人向けに引けない。

- `sso_sessions`・`sso_session_contexts`・`refresh_tokens` は**期限が来ると消える**（`expired_records`）。終わったログインは残らない。
- `audit_log` はテナントで引く索引しか無く、入り方・国・「どのログインか（sid）」の列も無い。`refresh_token.used` からは
  どのログインのトークンだったかが辿れない。

## 決定

1. **履歴を別の表に写して残す**（`sign_in_history`・`sign_in_app_usage`。migration 0070）。利用者を消せば消え、それ以外では消さない
   （監査ログと同じ）。ログイン 1 回の試みを 1 行、成功したログイン（`sid`）× アプリを 1 行にする。
2. **写す所は 3 つに絞る。**
   - 成功: web がログイン状態の Cookie を置いた応答（`/internal/devices/observe`。ADR-0071 と同じ口）。国（`CF-IPCountry`）は
     ここでしか分からない。作られて 2 分以内のセッションだけ、`sid` ごとに 1 回。
   - 断ったログイン: 監査ログの書き込み口を包む `SignInFailureRecordingSink`。`login.failed`・`login.locked`・`login.policy_denied`・
     `external_login.failed` のうち**利用者が定まるもの**を写す（知らないユーザー名は誰の履歴にも出さない）。経路が 7 つあるので
     経路ごとには足さない。`reason` は画面の言葉に写せる分類（`failure_kind`）へ丸める。
   - アプリへのトークン発行・更新・使い回しの検知: `TokenService`（`/token`）。
3. **リフレッシュの接続元は「送ってきた相手」として別に持つ。** アプリのサーバーが裏で更新するなら、そのサーバーの IP になる。
   ログインの接続元と同じ列に入れない（画面でも分けて書く）。
4. **取り消し・期限切れは写さず、読むときに `refresh_tokens` から数える。** 取り消しの経路（ログアウト・端末の取り消し・
   トークンの再発行・使い回しの検知・管理者の操作）は多く、写しを足すと漏れる。使える行があれば「有効」、期限内の行だけが
   残っていれば「取り消し済み」、どちらも無ければ「期限切れ」。
5. **国は ADR-0071 と同じ扱い。** web は `TRUST_FORWARDED_HEADERS` のときだけ読み、家の中から（homeedge 経由で）来た通信では入口が
   項目を消す。分からないときは「不明」と出し、推測しない。
6. **本人だけ。** 内部の口は SSO セッションの持ち主で利用者を決め、利用者 id を受け取らない。管理者は既存の監査ログを見る。

## 結果

- 「アカウントのセキュリティ」に「ログイン履歴」の欄が増え、新しい順に 10 件ずつ見られる。
- ⚠ **出ないもの**: assay を最初のログインにだけ使い、その後は自分のトークンで延ばすアプリ（fastapitemplate 系など）の延長。
  画面にその旨を書く。全アプリをまとめて見せるのは範囲外。
- ⚠ この機能より前のログインと、それより前に出したリフレッシュトークンの更新は履歴に無い。
- SAML でのログインは「ログイン」としては並ぶが、入った先のアプリ（SP）は出ない（トークンを出さないため）。
