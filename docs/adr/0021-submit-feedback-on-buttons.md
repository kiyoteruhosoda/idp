# ADR-0021: フォームの送信中は押したボタンにスピナーを出す

- 日付: 2026-08-03
- 状態: 採用
- 関連: ADR-0007（API/Web サービス分割）、`crates/web/assets/console.js`（破壊的操作の確認）

## 背景

web の画面はサーバレンダリングで、フォームを送ると次のページが返るまで表示は変わらない。
押せたのかどうかが利用者に返らないため、応答が遅いときは同じボタンが続けて押される。
ログイン・招待の発行・クライアント登録・テナント作成のように**押した回数だけ処理が走る**
操作でも、画面上はそれを止めるものが無かった。

管理コンソールには破壊的操作の確認ダイアログ（`console.js`）があるが、これは
「送るかどうか」を尋ねるだけで、送った後の状態は示さない。

## 決定

### 1. 送信中の目印は共通スクリプト 1 本で全画面に効かせる

`crates/web/assets/submit-feedback.js` を `/assets/submit-feedback.js` として自オリジン配信し
（`app.css` / `console.js` と同じ `include_str!` 同梱・`?v={asset_version}` 方式）、認証系画面
（`page.html`）と管理コンソール（`console/layout.html`）の**両方の共通レイアウト**が読み込む。

document 上の `submit` を 1 か所で受け、押された送信ボタン（`event.submitter`）へ Bootstrap の
スピナー（`.spinner-border.spinner-border-sm`）を差し込み、`aria-busy="true"` を立てて無効化する。
テンプレート側の記述は不要で、以後に追加する画面にも自動で効く。

### 2. 同じフォームの 2 度目の送信は止める

送信中の印（`form[data-submitting]`）が立っているフォームの `submit` は `preventDefault()` する。
ボタンの無効化だけでは、無効化が反映される前に届いた 2 度目を止められない。

### 3. 無効化は送信データが確定してから行う

`disabled` は `setTimeout(..., 0)` で送信開始後に付ける。submit ボタンを同期的に無効化すると
そのボタンの `name` / `value` が送信されない。同意画面（`consent.html` の approve / deny）と
言語切替（`console/layout.html`）は押したボタンの値で分岐しており、同期的な無効化は
**承認と拒否の区別を失わせる**。

### 4. 読み込み順は console.js の後にする

確認ダイアログで取り消された送信（`preventDefault()` 済み）に印を付けないよう、
`event.defaultPrevented` を見てから印を付ける。同じ要素のリスナは登録順に走るため、
`console/layout.html` では `console.js` より後に読み込む（順序は `templates.rs` の
テストで固定する）。

## 理由

- **テンプレートに手を入れない形にした。** 送信ボタンは 40 以上のテンプレートに散っており、
  1 つずつ属性を足す方式では追加した画面で書き忘れが起きる。押した瞬間に目印が出ることは
  画面ごとの選択ではなく、フォーム全体の既定の挙動として持たせる。
- **スピナーは押したボタンの中に出す。** 画面全体を覆うオーバーレイでは、押した場所と目印が
  離れ、同意画面のように並んだ 2 つのボタンのどちらが動いているのかが分からない。
- **見た目は Bootstrap のスピナーを使う。** 既に読み込んでいる CSS の範囲で足りるため、
  `app.css` に独自のアニメーションを増やさない。
- **戻るボタン対策を入れた。** bfcache から復元されたページは DOM がそのまま戻るため、
  `pageshow` で印を落とす（回りっぱなしで押せないボタンを残さない）。

## 影響

- 読み上げには `aria-busy="true"` で伝える。スピナーそのものは `aria-hidden` の装飾とし、
  訳文を JS 側に持たない（共通レイアウト `page.html` は `messages` を受け取らないため、
  翻訳リソース（`.ftl`）を唯一の出所とする方針を崩さずに文言を差し込めない）。
- `form.submit()` による送信（`saml_post.html` の自動 POST 中継）は `submit` イベントを
  発火しないため対象外。利用者が押す操作ではないので目印も不要。
- `type="button"` + `fetch` で進める画面（パスキーの登録・ログイン）は対象外。これらは
  それぞれの画面のスクリプトが段階表示を持つ。
