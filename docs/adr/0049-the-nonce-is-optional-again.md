# ADR-0049: `nonce` を仕様どおり任意に戻す

- 日付: 2026-09-10
- 状態: 承認

## 文脈

`/authorize` は **`state` と `nonce` の両方を必須**にしていた。`docs/OIDC_INPUT.md`
にも「OIDC 仕様上は任意だが、本IdPではポリシーとして必須化」と書いてある。

⚠ **OIDC Core 3.1.2.1 では、認可コードフローの `nonce` は任意である**
（必須なのは implicit / hybrid。⚠ **このサーバは `response_type=code` しか
受けない**）。つまり**仕様より厳しい**状態だった。

2026-09-10、その厳しさが実際に相手を弾いた。**Forgejo（git.nolumia.com）を
この IdP に繋ごうとして、ログイン画面にすら着けなかった。**

```
forge → idp   /authorize?...&state=...&code_challenge=...&code_challenge_method=S256   ⚠ nonce 無し
idp  → forge  error=invalid_request&error_description=nonce+is+required
```

⚠ **Forgejo 側は設定で足せない** ——`nonce` を送らないのは未実装で、機能要望として
上がっているだけである（forgejo/forgejo#186）。⚠ **`state` と PKCE(S256) は
送ってきている**（実測）。

## 決定

**`nonce` を任意に戻す。**

- ⚠ **`state` と PKCE(S256) は必須のまま。** コード奪取と CSRF の防御はそちらが
  持っている。⚠ **`nonce` が主に効くのは id_token のリプレイ**（implicit）で、
  コードフローではトークンは TLS の直通路（`/token`）で返る
- **送ってきた相手には、これまでどおり id_token の `nonce` に載せて返す**
- ⚠ **無いときはクレームごと出さない。** `"nonce": ""` を載せない
  （OIDC Core 2「認可要求に無ければ、載せるべきでない」）。
  ⚠ **これは refresh grant の id_token にも効く** ——そちらは以前から
  空文字を載せていた

## 影響

- ⚠ **緩める向きなので、いまの利用者は影響を受けない。** `nonce` を送っている
  クライアントの挙動は 1 つも変わらない
- ⚠ **`"nonce": ""` が消える。** 空文字を「一致するもの」として比べている実装が
  あれば影響するが、**そのような比較は仕様上できない**（無いときは検証しない）
- ⚠ **下流に `expect("nonce validated above")` が残っていた。** 必須をやめると
  そこで落ちる ——**DB 込みの統合テストで捕まえた**（単体だけでは通ってしまう）

## 検討したが採らなかった案

**Forgejo を fork して `nonce` を足す。** 上流に無い変更を抱えることになり、
**版を上げるたびに当て直す**。しかも直す理由は「この IdP が仕様より厳しいから」
であって、Forgejo の落ち度ではない。

**forge だけローカル口座で運用する。** ⚠ **名乗りが 1 つ増える** ——人を増やす
ときの手順も、止めるときの経路も別になる。IdP に寄せている流れに逆らう。

**`nonce` が無いクライアントだけ個別に許す**（クライアントごとの設定）。
⚠ **「この相手はどの規則で守られているか」が読めなくなる。** 仕様が任意と
言っているものを、こちらの設定項目に昇格させる理由が無い。
