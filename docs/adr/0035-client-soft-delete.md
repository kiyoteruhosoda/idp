# ADR-0035: クライアントの削除は論理削除にする

- Status: Accepted
- Date: 2026-08-26
- 関連: `docs/adr/0032-client-usage-drives-the-registration-form.md`、`docs/OIDC_INPUT.md` §7（監査ログ）

## 背景

OIDC クライアントには削除が無かった。作成・一覧・取得・更新・secret 再発行だけで、使わなくなった
クライアントは `DISABLED` にして一覧に残し続けるしかなかった（SAML SP には削除がある）。

削除を足すにあたり、物理削除にするか論理削除にするかを決める必要があった。

## 決定

### 1. 論理削除にする（実体は残す）

発行済みの認可コード・トークン・同意・**監査ログ**が `client_id` で紐づいている。実体を消すと、
監査で `client_id` を引いたときに「どのアプリだったか」を追えなくなる。

**削除の目的は「使えなくすること」であって「記録を消すこと」ではない。** 使えなくするだけなら
実体を残しても達成できるので、追跡可能性を捨てる理由が無い。

### 2. 別カラム（`deleted_at`）ではなく `client_status` の値を増やす

認可・トークン・introspection の各経路は、既に `Client::is_active()`（= status が `ACTIVE` か）で
門番をしている。`ClientStatus` に `Deleted` を足すだけで、**新しい絞り込みを 1 か所も書かずに**
全経路が削除済みを拒む。

`deleted_at IS NULL` 方式だと、経路ごとに条件を足して回ることになり、**足し忘れた経路だけ
削除済みが通る**という落とし方ができる。認可経路でそれが起きると、削除したはずのクライアントで
トークンが取れる。安全側に倒れる設計を選ぶ。

「いつ消したか」は監査ログ（`client.deleted`）と `updated_at` が持つので、専用カラムは要らない。

### 3. 管理操作からは「無い」ものとして扱う

`ClientManagementService::load` が削除済みを弾く。取得・更新・secret 再発行・再削除がまとめて
404 になり、経路ごとに `is_deleted()` を書く必要が無い（決定 2 と同じ理由）。

一覧・件数はリポジトリ側で `client_status <> 'DELETED'` を付ける。**絞り込みを足すのはここだけ。**

### 4. 復活させる導線は作らない

削除済みは一覧に出ず、状態の select（`ACTIVE` / `DISABLED`）にも `DELETED` は出さない。復活が
必要なら新しいクライアントを登録する。「消したはずのものが管理画面から戻せる」状態は、削除という
操作の意味を弱める。DB を直接触れる運用者が戻せることは妨げない（`client_status` を戻すだけ）。

## 影響

- `DELETE /{tenant_id}/admin/clients/{client_id}` を追加（204）。コンソールの詳細画面に削除ボタン
  （確認ダイアログ付き）を置いた。HTML フォームは DELETE を送れないため、web 側は POST で受けて
  api へ DELETE する。
- **削除は即座に効く。** 認可・トークン・introspection は `is_active()` で弾くため、`DISABLED` と
  同じタイミングで使えなくなる。発行済みアクセストークンの失効は別の話（有効期限まで有効）。
- マイグレーション 0044 は `CHECK` へ `'DELETED'` を足すだけの expand。ローリングデプロイ中に
  旧バイナリが混在しても、旧バイナリは `DELETED` を未知値として弾く（＝有効扱いしない）。
- 巻き戻し（0044 down）は `DELETED` を `DISABLED` へ倒す。`ACTIVE` へ倒すと**削除したはずの
  クライアントが再び使えるようになる**ため。

## 却下した案

- **物理削除（`DELETE FROM clients`）。** 監査で追えなくなる。外部キーの張り方次第では削除自体が
  失敗するか、関連行が道連れになる。
- **`deleted_at` カラム。** 「いつ」は取れるが、絞り込みを経路ごとに足す必要があり、足し忘れが
  認可経路に出ると削除済みで認証が通る。監査ログが「いつ」を持つので利点も薄い。
- **状態 select に `DELETED` を足して、そこから削除させる。** 削除は取り消せない操作なので、
  他の状態変更と同じ見た目・同じ導線に混ぜない。
