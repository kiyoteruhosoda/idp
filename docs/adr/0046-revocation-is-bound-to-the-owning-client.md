# ADR-0046: `/revoke` は、トークンの持ち主クライアントからの要求だけを受ける

- Status: Accepted
- Date: 2026-09-08
- 関連: RFC 7009 §2.1 / §2.2、
  `docs/adr/0044-ending-a-session-revokes-its-refresh-tokens.md`（失効の周辺）

## 背景

`/revoke`（RFC 7009）は実装済みで discovery にも載っているが、**トークンが要求元の
クライアントに発行されたものかを確かめていなかった。**

- `RevocationService::try_revoke_refresh_token` は認証済みクライアントを `_client` として
  受け取り、**使わずに捨てていた**。
- `RefreshTokenRepository::revoke` は `token_hash` だけを条件に消す（テナントもクライアントも
  見ない）。

結果として、**このテナントに登録されたクライアントなら、他のクライアントへ発行された
refresh token を消せた**。RFC 7009 §2.1 は「トークンがそのクライアントへ発行されたものか
検証し、失敗したら要求を拒む」と定めており、これを満たしていない。

実害は限定的である（消すにはトークンの値そのものを知っている必要がある）。だが
「値を知っていれば誰でも消せる」は、失効という操作の前提を崩している。

## 決定

**失効させる前に持ち主を確かめる。** `find_by_hash`（発行テナントも見る）で引き、
`client_id` が要求元と一致しなければ `unauthorized_client` で断る。

**不存在と持ち主違いを分ける。**

| 状態 | 応答 | 根拠 |
|---|---|---|
| そのテナントに該当の refresh token が無い | **200**（access_token として試し直す） | §2.2「無効なトークンはエラーにしない」 |
| 在るが、別のクライアントに発行されたもの | **`unauthorized_client`** | §2.1「検証に失敗したら要求を拒む」 |

一緒くたにエラーへ倒すと、**「エラーが返る＝そのトークンは実在して他人のもの」という
情報を問い合わせる口**になる。逆に一緒くたに 200 へ倒すと、いまと同じで検証が無いのと変わらない。

他テナント発行のトークンは `find_by_hash` がテナントで絞るため `None` に落ち、不存在と
同じ扱いになる（そもそも別テナントの存在を漏らさない）。

## 選択肢と理由

- **案A（採用）: 引いてから確かめ、持ち主違いは `unauthorized_client`。**
- 案B: 持ち主違いも黙って 200（何もしない）。情報は漏れないが、§2.1 の「拒む」を満たさず、
  **正しく実装したつもりの実装と区別が付かない**。不採用。
- 案C: リポジトリ側の `revoke` に `client_id` を足して 1 文で消す。往復は 1 回減るが、
  **「消せなかった」が不存在なのか持ち主違いなのか区別できなくなる**（どちらも 0 行）。
  応答を分ける以上、区別が要る。不採用。
- 案D: `revoke` の条件に `client_id` を足したうえで、0 行なら追加で引いて理由を判定する。
  結局 2 往復になり、案A より複雑。不採用。

## 影響

良い点:

- RFC 7009 §2.1 を満たす。
- 統合テストで 3 つを確かめている（`crates/api/tests/revocation_is_bound_to_the_owning_client.rs`）
  ——他のクライアントは消せない・**断ったときトークンが生きている**・持ち主は従来どおり消せる・
  不存在は 200 のまま。**修正を外すと落ちる**ことも確認した。

トレードオフ:

- refresh token の失効で **DB を 1 往復多く引く**（引いてから消す）。`/revoke` は
  頻度の高い経路ではないので許容する。
- 他人のトークンを提示したクライアントには `unauthorized_client` が返る。**そのトークンが
  実在することは伝わる**が、これは §2.1 が求める挙動であり、値を知っている相手にしか
  起こらない。

やり残し:

- `try_revoke_access_token` は JWT の `jti` を blocklist へ入れるだけで、**署名も持ち主も
  検証していない**（コメントに「署名検証は省略」とある）。任意の JWT 風文字列で `jti` を
  詰められる。本 ADR の範囲外だが、同じ性質の穴である。
