# ADR-0062: アカウントは本人が使えるようにする（ワンタイムリンク）

- Status: Accepted
- Date: 2026-09-21
- 関連: `docs/adr/0009-multi-tenant-architecture.md` §5（管理者による利用者作成・自動生成パスワード）、
  MT18（忘失時のパスワード再設定。同じトークンの表を使う）、
  `docs/adr/0025-login-identifier-registry.md`（パスキーを含む認証手段の並び）、
  `docs/adr/0032-client-usage-drives-the-registration-form.md`（逃げ道を書かない検証にしない）

## 背景

管理者が利用者を作ると、**assay が 32 文字のパスワードを生成して管理者へ返していた**。
`must_change_password` が立つので本人は初回ログインで変えることになるが、この形には 3 つの穴がある。

- ⚠ **管理者が本人の資格情報を一度手にする。** 渡すまでの間、管理者はその人になりすませる。
  変更を強制していても「最初の 1 回」は管理者の手を通る。
- ⚠ **渡す経路が平文になる。** 画面に出た文字列を、結局チャットや口頭で渡すことになる。
- ⚠ **パスキーだけで使い始められない。** 最初の 1 本を登録する画面はログイン済みでないと開けず、
  ログインするにはパスワードが要る。パスキーのログイン経路は既にあるのに、入口が塞がっていた。

メールで配る案は、この環境では機能しない。SES がサンドボックスのままで、家族の gmail には届かない
（それが届くようになるまで利用者を作れない、では本末転倒である）。

## 決定

### 1. 作成・再発行が返すのは**本人へ渡すワンタイムリンク**にする

```
POST /{tenant_id}/admin/users        → { user_id, sub, setup_url, setup_expires_at }
POST /{tenant_id}/admin/users/{id}/password-reset → { user_id, setup_url, setup_expires_at }
```

作成時、利用者の `password_hash` には**誰も知らない値**を入れる（生成はするが返さない）。
本人がリンクでパスキーを登録するかパスワードを設定するまで、そのアカウントでは誰も入れない。

再発行は従来どおり**いまのパスワードを即座に無効化**し、そのうえでリンクを出す。
「止める」と「入れ直せるようにする」は別の操作で、前者だけが要る場面（漏えい）があるため
無効化は残す。

### 2. リンクの用途を型で分け、パスキーを足せるのは**管理者が出したリンクだけ**にする

トークンは忘失時の再設定（MT18）と**同じ表**に置き、`purpose` 列（`reset` / `setup`）で分ける。
表を分けないのは、消費・失効・期限切れの判定が 2 本になって片方だけ直す事故が起きるからである。

⚠ **`reset` のリンクではパスキーを登録させない。** 「パスワードを忘れた」経路に認証器を足せると、
メールを一時的に読める相手が**居座る手段**を得る（パスワードなら次の再設定で切れるが、認証器は
残る）。

### 3. リンク先は**パスキーを主、パスワードを従**に置く

画面の主役は「パスキーを登録する」。パスワードは折りたたみの中に置き、使いたい人・使えない端末の
ために残す。どちらか一方で完了し、その時点でリンクは死ぬ。

パスキーだけで終えた利用者は、パスワードを**持たないまま**運用される。ログイン側は既に
discoverable credentials（ユーザー名を打たない形）に対応していて、⚠ **パスキーの経路は
`must_change_password` を見ない**ので、誰も知らないパスワードが残っていても妨げにならない。

### 4. ⚠ 開いただけでは消費しない

リンクは管理者が**チャットで渡す**ことを前提にしている。⚠ **チャットのプレビュー bot は、相手より
先に URL を取りに来る**（過去にワンタイムリンクを 1 本食われた）。したがって:

- `GET`（画面を開く）と `describe`（中身を読む）は**読むだけ**
- 消費するのは、実際に資格情報が決まったとき（パスワードの設定・パスキーの登録完了）だけ

パスキーは**登録が通ってから**消費する。先に消費すると、認証器の側で断られた相手がリンクも失う。

### 5. 渡し方は端末の共有シートに任せる

結果画面に「共有する」（`navigator.share`）と「コピーする」を並べる。共有シートを持たない環境では
共有ボタンを出さない（押せて必ず失敗するボタンを置かない）。⚠ CSP が `script-src 'self'` なので
値は data 属性で渡す。

### 6. リンクの寿命はテナント設定（既定 24 時間）

`ACCOUNT_SETUP_TTL_SECS`（`TenantOverridable`。ADR-0058）。再設定リンク（既定 1 時間）より長いのは
渡し方が違うからである —— 再設定は本人が「いま」押して自分のメールで受け取るが、設定リンクは
管理者が受け取って人づてに渡す。

## 影響

- **管理者は本人の資格情報を持たなくなった**（作成経路）。画面にも API にも生成パスワードは出ない。
- **パスキーだけのアカウントが作れるようになった。** パスワードを一度も決めずに運用できる。
- **リンクは 1 人につき 1 本。** 発行のたびに、その利用者の未使用リンクは失効する（再設定と同じ規則）。
- **`generated_password` は API から消えた**（2026-09-21。作成・再発行とも）。非常時の道具
  （deploy-repo の `host/breakglass`）も設定リンク経由へ移した（deploy-repo #73）。
  ⚠ **これで assay が管理者へ「使えるパスワード」を渡す経路は 1 つも無い。**
  再発行はいまも値を生成して置き換えるが、⚠ **その値は誰も知らない**（古い値を通らなく
  するためだけに在る）。
- ⚠ **「既知のパスワード × `must_change_password`」は管理 API では作れなくなった。** その状態を
  要る試験は、DB へ直に入れる（`crates/api/tests/support` の `force_password_change`）。
- ⚠ **単一オリジン構成では nginx の振り分けに `account-setup` が要る**（`docker/nginx.conf`）。
  足さないと api へ流れて 404 になる ——`crates/web/src/router.rs` の試験がこれを落とす。
- テナント作成時のブートストラップ管理者は**この変更の対象外**（root が自分のために作る経路で、
  リンクを渡す相手がその場にいる）。同じ形へ寄せるかは別途。

## 却下した案

- **リンクをメールで送る。** SES がサンドボックスで家族のアドレスに届かない。届く環境でも
  「作ったその場で渡す」道は必要になる（招待メールと同じく best-effort の追加機能にはできる）。
- **生成パスワードとリンクの両方を出す。** 管理者が資格情報を手にする形が残り、変更の目的が消える。
- **専用のトークンの表を新設する。** 消費・失効・期限切れの判定が 2 本になる。用途は列で足りる。
- **`reset` のリンクでもパスキーを登録できるようにする。** 決定 2 のとおり、メールを一時的に
  読める相手が居座れるようになる。
- **リンクを開いた時点で消費する。** プレビューの bot に食われる（実際に 1 本失っている）。
