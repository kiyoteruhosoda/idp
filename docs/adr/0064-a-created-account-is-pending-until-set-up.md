# ADR-0064: 管理者が作った利用者は、本人が設定を終えるまで仮登録にする

- Status: Accepted
- Date: 2026-09-24
- 関連: `docs/adr/0062-an-account-is-set-up-by-its-owner.md`（設定リンク）、
  `docs/adr/0057-the-roster-answers-who-may-use-this-application.md`（アプリの名簿）、`docs/adr/0063-member-notes-and-applications-on-the-member-page.md`

## 背景

ADR-0062 で、管理者が作った利用者には誰も知らないパスワードを入れ、本人へ設定リンクを渡す形にした。
本人がリンクでパスキーを登録するかパスワードを決めるまで、誰も入れない。

ところが状態は作った瞬間から `ACTIVE` で、メンバー一覧にも名簿にも「有効」と出ていた。
2026-09-24 に作った 2 人がまさにこの形で、画面からは「もう使える人」と区別が付かなかった。

入れないことは誰も知らないパスワードが守っていたが、それは**偶然の防御**である。たとえば外部 IdP の
結び付け・メールでの再設定は「有効な利用者」を相手にするので、本人がリンクを開く前に別の経路で
入口ができうる。

## 決定

### 1. 仮登録は `status` と直交する列で持つ

`users.pending_setup`（migration 0062）。`status` に値を増やさない。

仮登録は「有効 / 無効」とは別の事実である。仮登録のまま無効にし、また有効に戻せなければならない。
`status` に `PENDING` を足すと、有効に戻した瞬間に「本人がまだ何も決めていない」が失われる。

### 2. 仮登録は有効ではない（`User::is_active` が断る）

ログイン・トークン発行・管理コンソール・外部 IdP の結び付け・名簿の判定は、どれも `is_active` を通る。
`is_active` を `status == ACTIVE && !pending_setup` にすれば、1 か所でどこからも入れなくなる。
アプリの名簿（ADR-0057）でも仮登録の人は `blocked` になる。

### 3. 仮登録を終わらせられるのは設定リンクだけ

- 設定リンク（`purpose = setup`）の経路は `User::can_finish_setup`（無効でなければ可）で通す。
  パスキーを登録するか、パスワードを決めた時点で仮登録を外す。⚠ **リンクを消費する前に外す。**
  外せないまま消費すると、資格情報はあるのに入れず、リンクも無い人になる。
- ⚠ **忘失時の再設定リンク（`purpose = reset`）では仮登録を終わらせない。** 仮登録の人には
  「パスワードを忘れた」から再設定リンクも出さない。メールを一時的に読める相手に、本人より先に
  入口を作らせないため。本人は設定リンクを持っている。失くしたら管理者が「パスワード再発行」で出し直す。
- 無効にされた人は、仮登録でも手元のリンクで設定を終えられない。

### 4. 仮登録で作るのは管理者の作成だけ

自己登録は本人がその場でパスワードを決めているので仮登録ではない。管理者の再発行は、既に設定を
終えた人に対するものなので仮登録へ戻さない。

## 移行

migration 0062 は、既に在る「作られたが、まだ設定されていない」利用者を仮登録へ倒す。条件は
「作成から 1 分以内に出た設定リンクがあり、どの設定リンクも使われておらず、認証器が無く、
パスワード変更がまだ要る」。管理者の再発行で後から出たリンクは対象にしない。

## 結果

- メンバー一覧と詳細に「仮登録」と出る。詳細には、なぜ入れないのかと、リンクを出し直す方法を添える。
- 試験で「管理 API で作った人を、そのまま SSO セッションの持ち主にする」形は通らなくなった。
  本人が設定を終えた代わりに `support::finish_setup` を呼ぶ。
