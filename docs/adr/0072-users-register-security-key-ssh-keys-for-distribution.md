# ADR-0072: SSH の鍵は利用者が sk 型だけを自分で登録し、機械クライアントが読んで配る

- Status: Accepted
- Date: 2026-11-04
- 関連: task #885（親 #876「持ち主の SSH の鍵をセキュリティキーへ」・設計 第 3 版）、task #886（配る側。deploy-repo の
  `host/sshkeys`）、ADR-0071（パスキーで 5 分以内・セキュリティの知らせ）、ADR-0037（管理 API と細粒度コード）、
  ADR-0069（細粒度コードは管理者へ届かない）

## 背景

持ち主の SSH の鍵は PC のファイル（`ssh-ed25519`）で、PC がウイルスに乗っ取られると鍵ファイルとパスフレーズを持ち出され、
後から持ち主の知らないうちに nolumialab・naso・ASUS へ入られる。鍵の足し外しは Claude が各機器の authorized_keys を
手で書き換えていた。

## 決定

1. **登録できる鍵は sk 型だけ**（`sk-ssh-ed25519@openssh.com`・`sk-ecdsa-sha2-nistp256@openssh.com`）。秘密鍵が
   セキュリティキー・TPM（Windows Hello）・スマホのパスキーの中にあり、PC には持ち出しても単独では使えない持ち手しか
   残らない。使うたびに機器での確認が要る。ファイルの鍵（`ssh-ed25519`・`ssh-rsa`・`ecdsa-sha2-*`）は断る。
2. **公開鍵は形まで確かめる。** 1 行の `型 本体 [コメント]` だけを受け、本体を開いて OpenSSH の並び（型・鍵・application）
   として読めること、中の型が 1 つ目の欄と一致すること、長さが型どおりで余りが無いことを見る。コメントは保存しない
   （配る行は `型 本体` だけ）。指紋は `ssh-keygen -l` と同じ `SHA256:…`。`PRIVATE KEY` を含む入力は**中身を読まずに**
   断り、web は api へも渡さない。同じ組織に同じ指紋は 1 本だけ（別の利用者でも）。1 人 10 本まで。
3. **登録も取り消しもパスキーで確かめてから 5 分以内だけ**（step-up の `manage_ssh_keys`。`passkey_only`）。確かめ方は
   ADR-0071 と同じ（`amr` にパスキーがあり `auth_time` が 5 分以内か、パスキーで step-up してから 5 分以内）。
   パスワードを盗んだだけの者に鍵を足させず、本人の鍵を外して締め出させもしない。
4. **登録・取り消しは必ず監査ログに残し、セキュリティの知らせへ送る**（ADR-0071 の Webhook）。端末の知らせの設定
   （`UNREGISTERED_DEVICE_ALERTS_ENABLED`）とは別に、機能を有効にした組織では常に送る —— 鍵を足すのは機器へ入る道を
   増やすことで、端末の登録より重い。
5. **組織ごとに有効・無効（`SSH_KEYS_ENABLED`、既定 false）。** assay は複数の組織で使う。無効の組織では画面に欄を出さず、
   配る一覧は空。登録済みの行は消さない。鍵は登録した組織ごとに持つ。
6. **配る口は管理 API の `GET /{tenant_id}/admin/ssh-keys`、コードは `idp.ssh-keys:read`。** ⚠ **機械クライアントの
   トークンだけを通す。** コードは `idp.tenant.admin` が含意する（テナント管理者がクライアントへ付けられる。ADR-0069 の
   `may_assign` は呼び出し元が含意するコードしか配らせない）が、口は人の管理トークンを 403 で断る。一覧は公開鍵だが、
   「誰のどの鍵がどの機器に通るか」の地図になるので、ブラウザ（乗っ取られうる側）から集めさせない。
7. **一覧に出すのは、有効な利用者（仮登録でない）で、その組織の有効なメンバーで、利用者名を持つ人の鍵だけ。**
   止めた・組織から外れた人の鍵は、行が残っていても配られない。各要素は `username`・`name`・`public_key`（`型 本体`）・
   `fingerprint`・`created_at`。

## 結果

- 持ち主は sk 型の鍵を作って assay に貼るだけで、数分のうちに各機器へ配られる（配る側は task #886）。Claude の手作業が要らない。
- ⚠ **防げないこと**: assay のパスキーそのものを使われた場合（鍵を足せる）・持ち主が機器で確認したその 1 回の横取り・
  開いている SSH の画面への打ち込み。足した・外したは毎回知らせが届くので、気付くことはできる。
- 取り消しは assay の一覧から外すだけで、機器から消えるのは配る側が次に読んだとき（数分）。

## 却下した案

- **短い SSH 証明書を assay のパスキーで出す**（#876 の第 2 版）。登録が要らないが、ASUS（dropbear）が証明書を受け付けず、
  CA の秘密鍵という新しい守り物が増える。持ち主が「公開鍵を自分で登録する画面」を選んだ。
- **ファイルの鍵も受け付ける。** 鍵ファイルを盗まれる話そのものを防げなくなる。
- **一覧を人の管理トークンでも読めるようにする。** 管理コンソールに見せる必要が無く、読める主体を増やすだけになる。
