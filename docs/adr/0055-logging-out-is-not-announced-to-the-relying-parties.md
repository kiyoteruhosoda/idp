# ADR-0055: ログアウトでは RP へ知らせない（知らせるのは管理者が止めたときだけ）

- 日付: 2026-09-15
- 状態: 採用
- 関連: ADR-0024（`sid` と配送キュー。ログアウトで通知を積む部分をこの ADR で置き換える）、
  ADR-0053（停止の通知）、ADR-0044（ログアウトで refresh token も失効させる）、
  `docs/RP_INTEGRATION.md` の 5・6

## 背景

assay は back-channel logout の通知を 2 つの場面で積んでいた。

| 場面 | 載せるもの | RP 側で閉じるもの |
|---|---|---|
| 管理者が利用者を止める（無効化・パスワード再発行・MFA 解除。ADR-0053） | `sub` | その利用者の全セッション |
| SSO セッションが終わる（RP-initiated logout。ADR-0024） | `sub` ＋ `sid` | そのセッションで入った各 RP のセッション |

後者は OpenID Connect の single logout で、仕様としては正しい。しかし SSO セッションは、
同じ利用者が使う複数の RP で共有されている。SSO 専用の RP（codelab）はサインアウトを
assay まで通すので、⚠ **codelab でサインアウトすると、同じブラウザで SSO で入っていた
他の RP のセッションまで閉じる**ことになる。利用者が頼んでいない副作用である。

これまで表に出なかったのは、`backchannel_logout_uri` を登録した RP が 1 つも無かったから
にすぎない（2026-09-15 に本番で確認: 24 件中 0 件）。ADR-0053 の停止の通知を効かせるために
登録すると、同時にこの副作用も生まれる。

## 決定

- **RP-initiated logout では back-channel logout の通知を積まない。** SSO セッションの終了・
  未消費の code の失効・そのセッション由来の refresh token の失効（ADR-0044）は従来どおり行う。
- RP へ知らせるのは**管理者が利用者を止めたときだけ**（ADR-0053。`sid` は付けない）。
- 配送キュー（ADR-0024）はそのまま残し、停止の通知が使う。
- front-channel logout も同じ性質を持つが、登録している RP が無いので今回は触れない。
  ⚠ **登録すると同じ副作用が戻る。**

## 理由

- サインアウトの範囲は RP が決める（`RP_INTEGRATION.md` の 6）。ローカル口座も持つ RP は、
  共有の SSO セッションを切らないと決めている。assay がログアウトを配ると、RP のこの決定を
  IdP の側で上書きすることになる。
- 捨てた案:
  - **クライアントごとに「ログアウトでも受け取る」を選べるようにする** —— 仕組みとしては
    素直だが、いま選ぶ RP が 1 つも無い。使う RP が出たときに足せば足りる。クライアントの
    スキーマはアプリの段（ADR-0054）の作業とも重なるので、いまは触らない。
  - **RP の側で `sid` 付きの通知を無視する** —— 方針が 7 本の RP へ散り、1 本でも直し漏れれば
    副作用が戻る。
  - **codelab のサインアウトを assay まで通さない** —— SSO 専用の RP では、通さないと
    サインアウトした次の瞬間に黙って再ログインする（`RP_INTEGRATION.md` の 6）。

## 影響

- assay の SSO セッションを終えても、他の RP のセッションは続く。他の RP は、次に SSO で
  ログインするときに名乗り直しを求められる。
- `logout_token` に `sid` が載ることはなくなる。RP の受け口にある `sid` の処理は残してよい
  （害は無い）が、`sid` 必須で書いた受け口は何もしない。
- 標準の single logout が要る RP が出たら、この ADR を置き換えて opt-in を足す。
