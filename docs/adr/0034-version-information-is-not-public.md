# ADR-0034: 稼働中のビルド情報は公開面に出さない

- Status: Accepted
- Date: 2026-08-26
- 関連: `docs/adr/0031-health-endpoint-disclosure.md`（決定 1 の基準・積み残し）、
  `docs/adr/0033-resource-server-authorization-belongs-to-the-application.md`

## 背景

ADR-0031 で「公開面（`/healthz`・`/readyz`）に載せるのは、**秘密ではなく、かつ攻撃者の役に立たない**
ものだけ」と決め、版数・コミットハッシュはその基準を満たさないとして積み残しにした。

改めて数えると、無認証で読めていたものは `/version` だけではなかった。

| 面 | 出ていたもの |
|---|---|
| **全公開ページのフッター** | `IdP Web v0.1.0 (abc1234)` —— **ログイン画面にも出ていた** |
| web `GET /version` | 上記＋DB の適用済み／期待スキーマ version |
| api `GET /version` | パッケージ版・Git 版 |
| api `GET /version/schema` | 適用済み／期待スキーマ version・DB 読み取り可否 |

**本丸はフッターだった。** `/version` だけを塞いでも、ログイン画面を開けばコミットハッシュが読める。
稼働中のコミットが分かるということは、**どの既知の不具合がまだ塞がっていないかを外から判断できる**
ということである。Swagger UI を既定で伏せている判断（SEC12）と同じ理由で、これも伏せる。

一方で、この画面は**目的があって作られた**ものでもある。DB を直接見られない管理者が、
migrate 未適用を画面から確認できるようにするために追加された。塞ぐだけでは、その要求が失われる。

## 決定

### 1. 完全公開ページのフッターから版数を外す

`page.html`（ログイン・パスワード再設定・エラーページ等）のフッターは製品名のみにする。
運用者向けの版数は、次の 2 か所から読める。

### 2. バージョン画面は管理コンソールの内側へ移す

`GET /version` を廃し、`GET /{tenant_id}/admin/version` にする。コンソールのフッターは従来どおり
版数を表示し、そこから本画面へ入れる（**入口は変えていない。認証の有無だけが変わった**）。

DB を直接見られない管理者がスキーマの適用状況を確認できる、という当初の目的はログイン済みには
そのまま残る。画面の文言はコンソールの他画面と揃えて i18n 化した。

### 3. api の版数エンドポイントを内部面へ移す

`GET /version` → `GET /internal/version`、`GET /version/schema` → `GET /internal/version/schema`。
`/internal/*` はプロキシ遮断＋サービストークンの二重（ADR-0031 決定 2）。web は既に
サービストークンを持っているため、コンソールの画面はそのまま動く。

**`fetch_schema_version` はトークンを付けていなかった**ので、付けた。公開エンドポイントを
前提にした実装だったためで、移設と同時に直さないと画面が「取得できません」になる。

## 影響

- **ログイン画面からコミットハッシュが読めなくなった。**
- `GET /version`（web・api）と `GET /version/schema`（api）は **404 になる**。監視や配置検証が
  これらを叩いていれば影響を受ける。同じ情報は `GET /internal/health`（ADR-0031）が返す。
- 管理コンソールのフッターのリンク先が `/version` → `/{tenant_id}/admin/version` に変わった。
- api の版数は `/internal/health` の `version` にも含まれるため、`/internal/version` は
  「版数だけが欲しい」ときの軽い口として残している。

## 却下した案

- **バージョン画面ごと消す。** `/internal/health` が同じ情報を返すので重複ではある。しかし
  そちらはコンテナの中からしか読めず、**「DB を直接見られない管理者」という当初の対象と
  読み手が違う**。画面を消すと、その人たちが migrate 未適用を確認する手段を失う。
- **公開のまま、版数だけを伏せてスキーマ状態は出す。** 適用済みマイグレーション番号も
  「どの機能・修正が入っているか」を語るので、基準は版数と変わらない。
- **フッターの版数を全ページで残し、`/version` だけ塞ぐ。** 塞いだつもりで塞げていない
  （ログイン画面にハッシュが出たまま）。積み残しを作った当初の私の見立てがこれだった。
