# ADR-0048: 画面はスマートフォンで読まれる —— 表はカードへ、時刻は閲覧者の時刻へ

- Status: Accepted
- Date: 2026-09-09
- 関連: `crates/web/assets/app.css`（`.table-cards`）、
  `CLAUDE.md`「国際化（i18n）」の表示言語の決定チェーン（MT20）、
  HANDOVER §14（時刻は UTC で持つ）

## 背景

セキュリティ画面（`/{tenant_id}/settings/security`）をスマートフォンで開いたところ、
**表の中身が読めない状態になっていた**。

- アプリ名 `codelab` が **`cod` / `ela` / `b` と 1 文字ずつ縦に割れる**。列幅が
  端末の幅を超えて配分され、どの列も潰れる
- 連携日時が `2026-09-04T23:42:07.62` で**右端に切り落とされる**。横スクロールの
  中に残りがあるが、スクロールできることは画面から読めない
- User-Agent の文字列が同じ表の中で最も幅を食い、他の列を押し潰す

原因は 2 つあり、**どちらも「既にある仕組みを使っていなかった」**という形だった。

1. **狭い画面で表をカードへ組み替える仕組み（`.table-cards`）が付いていなかった。**
   管理コンソールの 13 の表は 2026-09-02 からこれを使っていて、`app.css` に規則も
   ある。付け忘れた 3 画面（セキュリティ・認証器・認証ポリシー）だけが素の
   `.table-responsive` のまま残っていた。
2. **時刻を RFC 3339 の文字列のまま出していた。** api は UTC の
   `2026-09-09T11:20:04.512345Z` を返す。これは機械のための表記で、**桁が長いうえに
   閲覧者の時刻ですらない**（JST の利用者には 9 時間ずれた数字が見えている）。

## 決定

**画面は狭い端末で読めることを条件とし、時刻は閲覧者のタイムゾーンで描く。**

### 表はすべてカードへ組み替える

`<table>` には必ず `.table-cards` を付け、各 `<td>` に列見出しと同じ翻訳を
`data-label` で持たせる（操作ボタンのセルは除く）。**例外を作らない**ため、
テンプレートを直接走査するテストを置いた（`every_table_collapses_into_cards_on_narrow_screens`）
——**付け忘れは画面を狭い端末で開くまで誰も気付かない**。今回も、指摘されるまで 3 画面が
残っていた。

### 時刻は「機械の値」と「人の値」を分けて出す

```html
<time class="local-time" datetime="2026-09-09T11:20:04.512345Z">2026-09-09 11:20 UTC</time>
```

- `datetime` 属性は api が返した値のまま（機械・支援技術が読む）
- 要素の中身は `templates::utc_short` が作る `YYYY-MM-DD HH:MM UTC`
- `assets/local-time.js` が中身を `Intl.DateTimeFormat` で閲覧者の表記へ差し替える

**中身をサーバー側で「読める形」にしておくのが肝**である。差し替えが起きなかったとき
（JS が無効・読み込み失敗）に残るのがこの値で、そこに生の RFC 3339 を置くと、いま起きて
いた問題がそのまま残る。**UTC と明示する**のは、差し替わらなかった時刻を利用者が自分の
時刻だと読み違えないため。

言語は **`<html lang>` から取る**（ブラウザの言語ではない）。画面の言語は利用者が選べる
（MT20 の決定チェーン: `?lang=` > 利用者設定 > Cookie > `ui_locales` > ブラウザ）のに、
日付だけブラウザの言語で出ると読み手が混乱する。

## 選択肢と理由

- **案A（採用）: サーバーは UTC の短縮形を出し、ブラウザが閲覧者の時刻へ差し替える。**
- 案B: サーバー側でタイムゾーンを解決して出す。**サーバーは閲覧者のタイムゾーンを
  知らない**（Cookie に持たせるか、利用者設定に足すことになる）。時差の情報はブラウザに
  最初からあるので、そこへ寄せる。不採用。
- 案C: 表示用に整形済みの文字列を api が返す。api は機械の口でもあり、**表示の都合を
  混ぜると機械側が困る**（RFC 3339 を期待している）。整形は画面の仕事。不採用。
- 案D: 狭い画面では列を減らす（重要な列だけ出す）。**どの列が要らないかは利用者による**
  ——IP アドレスを見たい人と、いつログインしたかを見たい人が同じ表を見る。カードなら
  全部を順に出せる。不採用。

### 折り返さない塊も読める形にする

`<pre>`（JWKS の JSON・traceback）は既定で行の途中を折り返さないため、狭い画面では
画面の外へ伸びる。`.pre-wrap`（`white-space: pre-wrap` ＋ `overflow-wrap: anywhere`）を
足して、**改行を保ったまま**長い行だけ折る。Bootstrap の `.text-wrap` を当てると
`white-space: normal` になって traceback の改行が消えるので使わない。

操作ボタンのセルに付いていた `.text-nowrap` も外した。表では折り返さないほうが読めるが、
カードでは幅が狭いため、折り返せないと外へはみ出す。

## 影響

良い点:

- 3 画面（セキュリティ・認証器・認証ポリシー）が狭い端末で読めるようになった。
  列が潰れず、値が切れず、横スクロールも要らない。
- 時刻を出す 15 か所すべてが閲覧者の時刻になった（管理コンソールの監査ログ・
  アプリケーションログ・署名鍵・クライアント詳細・クライアント状況・招待と、
  利用者側のセキュリティ・パスキー・認証器）。マイクロ秒の桁も消えた。
- 列見出しの「（UTC）」を外した（監査ログ・最終利用・署名鍵の有効期間）。**値が
  閲覧者の時刻になった以上、見出しが嘘になる。** 検索欄のヒント「RFC 3339（UTC）」は
  入力の形式を指すので残した。
- 表の付け忘れはテストで落ちる。新しい表を足す人は `data-label` まで書くことになる。

トレードオフ:

- **JavaScript が動かない環境では UTC のまま**である。時差のある利用者には正しくない
  時刻が見えるが、`UTC` と明示してあるので**読み違えではなく読み替え**になる。
- 差し替えは描画後に起きるため、遅い端末では一瞬 UTC が見える。`defer` で読み込む
  スクリプト 1 本ぶんの遅れで、値そのものは最初から読める形なので許容する。

やり残し:

- **`<html lang>` を出せているのは管理コンソールだけ。** 利用者向けの `page.html` は
  `MessagePage` / `ErrorPage`（翻訳済み文字列だけを受け取り `Messages` を持たない）でも
  使うため、いまは属性を置いていない。その 2 つに言語を持たせれば揃う（Progress の T43）。
  この間、利用者向け画面の日時はブラウザの言語で整形される。
