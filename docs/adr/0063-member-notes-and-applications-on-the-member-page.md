# ADR-0063: メンバーの画面に管理者メモと使えるアプリを置き、管理コンソールをインストールできるようにする

- Status: Accepted
- Date: 2026-09-24
- 関連: `docs/adr/0009-multi-tenant-architecture.md` §3（ゲストの利用者は所属元の管理者しか触れない）、
  `docs/adr/0054-applications.md`（アプリと割り当て）、`docs/adr/0058-settings-are-decided-by-the-tenant.md`（割り当ての段階導入はテナントが決める）

## 背景

管理コンソールのメンバーまわりに、運用で困っていることが 4 つあった。

- **どういう経緯のアカウントかを残す場所が無い。** 家族・取引先・試験用など、作った理由は
  管理者の記憶にしか無い。
- **その人がどのアプリを使えるかが分からない。** アプリの詳細から「誰が使えるか」は見えるが、
  人の側から逆に引く画面が無く、アプリを 1 つずつ開いて探すしかなかった。
- **メンバー一覧が読みにくい。** 列が 6 つ（メール・ユーザー名・種別・メンバーシップ・アカウント・
  操作）あり、スマホのカードでは 1 人が見出し付きの 6 段になって画面に 2 人しか入らない。
  全員に「HOME」「ACTIVE」「有効」が並ぶので、止まっている人が埋もれる。
- **スマホのホーム画面へ入れられない。** Chrome が「このアプリはインストールできません」と出す。
  マニフェストが無く、アイコンも SVG 1 枚だけだった。

## 決定

### 1. 管理者メモはメンバーシップに付け、別表に置く

`tenant_member_notes (tenant_id, user_id, note, updated_at, updated_by)`（migration 0061）。

- **利用者ではなくメンバーシップ**（テナント × 利用者）に付ける。メモはテナントの管理者が持つ事実で、
  同じ人でも HOME とゲスト先では書くことが違う。ゲストにも書ける ——ゲストの利用者そのもの
  （ADR-0009 §3）を変えるものではない。
- `tenant_memberships` の列にしない。招待・承諾・停止の全 SELECT と `TenantMembership` を巻き込むうえ、
  トークンや userinfo へ写す経路の近くに自由記述を置くことになる。読むのはメンバー一覧・詳細の結合だけ。
- メンバーシップが消えればメモも消える（複合外部キーで CASCADE）。ゲストを解除して招き直したとき、
  前回のメモが黙って戻る形にはしない。
- 上限は **2000 文字**（文字で数える）。値は契約 crate（`assay_contracts::admin::MEMBER_NOTE_MAX_LEN`）に置き、
  api の検証と web の `maxlength` が同じ値を読む。
- ⚠ **監査にメモの中身を載せない。** 経緯の自由記述には個人の事情が入る。残すのは誰が誰のメモを
  書いたか・消したか（`tenant_membership.note_updated`）だけ。
- メモの言葉で一覧を絞り込める（「〇〇経由で招いた人」を経緯から引く）。

### 2. 使えるアプリは判定と同じ規則で答える

`GET /{tenant_id}/admin/members/{user_id}/applications`（`idp.applications:read`）。

- 可否は code の発行地点と同じ `Application::admits` で決める。画面が別の規則で答えると
  「使えると出ているのに入れない」が起きる。
- 載せるのは**ログインの名乗り（OIDC / SAML）を持つアプリだけ**。サービスアカウントや宛名しか
  持たないアプリは人が入る先ではない。
- メンバーの画面から「個別」のアプリへ割り当て・解除ができる。呼ぶのはアプリの詳細と同じ API で、
  規則（メンバーであること・冪等）は 1 か所にしか無い。「全員」のアプリには出し入れの口を出さない。
- `idp.applications:read` を持たない管理者には、メンバーの画面ごと断らずアプリの欄だけを出さない。

### 3. 一覧は「誰か・状態・メモ」の 3 列にし、普通でないものだけを札にする

- 見出しはメール（無ければユーザー名）。その下にユーザー名と氏名を小さく添え、見出しと同じ値は繰り返さない。
- 状態はゲスト・停止中・招待中・無効・ロック中だけを札にする。普通の人は「有効」を淡く出す。
- 操作列は落とし、行（カード）のどこを押しても 1 人の画面へ行く。

### 4. マニフェストはテナントごとに、認証の外に置く

`GET /{tenant_id}/admin/manifest.webmanifest`。`start_url` / `scope` は `/{tenant_id}/admin`、
`id` はテナントごとに分け、複数テナントの管理コンソールを別のアプリとして並べられるようにする。

- ⚠ **認証の外に置く。** ブラウザはマニフェストを Cookie 無しで取りに来る。ログイン画面へ 302 すると
  HTML をマニフェストとして読んでインストールできない。中身は定型文でテナントの名前も載せない。
- ログイン画面にも `<link rel="manifest">` を置く。ログアウトした状態で開いた画面からも入れられるように。
- アイコンは 192px / 512px の PNG と maskable の 512px（`assets/icons/`。絵は `assay.svg` と同じ）。
- **service worker は置かない。** Chrome のインストール条件はマニフェストとアイコンで満たせる。
  認証の後ろの画面を持つアプリでは、スクリプトの取得がログインへ飛ばされると登録ごと失われる。
  オフラインで見せられるものも無い。

## 結果

- 経緯はメモに、使えるアプリは人の画面に集まる。「この人は何者で、どこに入れるか」が 1 画面で分かる。
- ⚠ マニフェストに名前を載せないので、複数テナントを入れるとホーム画面ではどれも「assay」になる。
  開けばヘッダにテナント名が出る。名前を載せるには認証の外でテナント名を引く口が要り、今回は見送った。
